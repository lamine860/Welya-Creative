# AGENTS.md

## Cursor Cloud specific instructions

**Product:** Welya Creative — a single Laravel 12 app (PHP 8.4) with a React 19 + Inertia.js + TypeScript + Vite 7 frontend, a Filament 4 admin panel at `/cp`, and Laravel Fortify auth. Data lives in SQLite (`database/database.sqlite`) by default.

### Environment gotchas
- There is **no `.env.example`** committed in this repo (CI references one, but it is missing). The dev `.env` is created during environment setup and persists in the VM snapshot; it is gitignored. If `.env` is ever missing, recreate it with SQLite defaults (`DB_CONNECTION=sqlite`, database/cache/session/queue drivers) and run `php artisan key:generate`.
- The database is a local SQLite file at `database/database.sqlite`. It is already migrated and seeded in the snapshot. To reset: `php artisan migrate:fresh --seed`.
- Seeded admin user for `/cp`: **mlamine860@gmail.com** / **passwordABC** (see `database/seeders/DatabaseSeeder.php`).
- Wayfinder generates `resources/js/{routes,actions,wayfinder}` (all gitignored). These are auto-generated by the `@laravel/vite-plugin-wayfinder` plugin whenever Vite runs (`npm run dev` or `npm run build`). Before those files exist, `npm run types` (tsc) fails with `Cannot find module '@/routes'` — run a build/dev first.

### Running the app (development)
- All-in-one: `composer dev` (runs `php artisan serve` on :8000, `npm run dev` Vite on :5173, queue listener, and Pail log tail concurrently).
- Or run individually: `php artisan serve` and `npm run dev`.
- Inertia SSR is **enabled** in `config/inertia.php` (`url` :13714) but `composer dev` does NOT start an SSR server; pages still render fine via client-side rendering in dev. For SSR-accurate runs use `composer dev:ssr` (builds the SSR bundle first, then starts SSR on :13714).
- Key URLs: `/` (public site), `/contact` (contact form), `/login`, `/dashboard` (auth), `/cp` (Filament admin), `/up` (health check).

### Lint / test / build
- PHP lint: `vendor/bin/pint` (auto-fixes) or `vendor/bin/pint --test` (check only). Note: the current repo has pre-existing Pint/ESLint/Prettier style deviations; CI auto-fixes them, so `--test`/dry-run modes report failures that are not from your changes.
- Frontend: `npm run lint` (eslint --fix), `npm run format` / `npm run format:check` (prettier), `npm run types` (tsc, requires Wayfinder files — run a build first).
- Tests: `composer test` or `./vendor/bin/pest` (uses in-memory SQLite; no extra setup needed).
- Build: `npm run build` (assets) / `npm run build:ssr` (assets + SSR bundle).
